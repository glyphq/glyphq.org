A transaction looks wrong. You have a hash, but the useful question is what happened before and after it: which identity sent it, which tick included it, and which contract call it touched.

Glyph Explorer answers that with linked pages over public Qubic data. It shows network health, ticks, transactions, identities, tokens, and contracts in a readable form, without exposing raw RPC responses.

## What you can open

An identity page collects balances and activity for one address. A transaction page shows the transaction and its tick. A contract page connects the visible state to the generated metadata for that contract.

Start with the identity when you need to know whether a balance changed and which transactions caused it. Start with the tick when you need to know whether the network was moving around the time a transaction should have landed.

The tick view is a useful sanity check before a deeper investigation. If the latest ticks are healthy and the transaction is missing, the problem is more likely in the transaction path than in the network as a whole.

## Link to a record

The explorer routes are predictable, so an app can send someone directly to a record:

```ts
const explorer = "https://explorer.glyphq.org";

const accountUrl = (identity: string) => `${explorer}/accounts/${identity}`;
const transactionUrl = (hash: string) => `${explorer}/transactions/${hash}`;
const tickUrl = (tick: number) => `${explorer}/ticks/${tick}`;
const contractUrl = (name: string) => `${explorer}/contracts/${name.toLowerCase()}`;
```

Keep the link beside the record it describes. A user who receives a transaction notification can open the transaction page and move to the identity or tick without searching again.

<Callout type="tip" title="Use the identity page as the starting point">
  Most questions about a payment resolve on the identity page: whether the balance changed and which transactions touched it. The transaction and tick pages supply the surrounding detail.
</Callout>

## For development

The explorer is a quick way to check what a transfer or contract call did before you write a query against an index. For repeated reads, streams, or historical analysis, use [Glyph API](/products/api), which is the public data API in the same stack.
