A browser wallet asks you to trust a tab. Glyph Wallet is a native desktop app that keeps your Vaults on your machine and turns each request from a connected app into a separate review.

The wallet has two jobs. It stores the Qubic identities you use and it signs only after you approve a specific request. The app is built with Tauri v2, React, TypeScript, and Rust, with builds for Windows, macOS, and Linux.

A Vault holds one or more Qubic identities. Those identities can send QU, sign data, or answer a contract call, and the private material stays in the local Vault. Glyph does not keep a hosted account that can recover it for you.

The desktop model matters when an app asks for a signature. The wallet can show the recipient, amount, contract input, or message beside the account that will sign it. You approve or reject that request, and the result goes back to the app through a callback, a redirect, or Glyph Relay.

## A request from an app

Glyph Connect builds a transfer request, wraps it in an envelope, and opens the wallet. The wallet receives the envelope and presents the details for review.

```ts
import {
  createEnvelope,
  createTransferRequest,
  launchGlyphRequest,
} from "@glyph-oss/connect";

const request = createTransferRequest({
  type: "transfer",
  dapp: { name: "Example", origin: "https://example.app" },
  to: recipientIdentity,
  amount: "1000",
});

const envelope = createEnvelope(request, {
  callback: "https://example.app/api/glyph/callback",
});

launchGlyphRequest(envelope);
```

The callback URL must use HTTPS and match the dApp origin. The request is separate from a connection request, so a dApp can ask for a connection once and still require approval for each transfer or signature.

The Linux build is a single AppImage:

```bash
chmod +x Glyph_*_amd64.AppImage
./Glyph_*_amd64.AppImage
```

Windows uses the per-user setup executable, and macOS uses the universal DMG.

<Callout type="warning" title="The seed is the recovery path">
  Glyph cannot recover a seed or reset a forgotten Vault password. Store the seed offline and test a backup before you need it.
</Callout>

The wallet is the point where a request becomes a decision. The rest of the stack prepares the request and carries the result; the approval happens here.
