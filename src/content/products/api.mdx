title: Glyph API

Every query against a remote index inherits the remote's choices: which peers it trusts, how long it keeps history, and what it does when a peer returns bad data.

Glyph API puts those choices in your infrastructure. It connects to Qubic peers over TCP, verifies what they return, stores normalized history in ClickHouse, and serves reads from the verified local head.

## The data path

The service starts with peers. It receives ticks and the records that come with them over the native TCP protocol, checks quorum vote groups, and writes a tick only after it reaches a verification tier.

<FeatureList

ClickHouse holds the normalized history. The API reads that store and returns resources for identities, transactions, ticks, tokens, contracts, and network status. The same store supports analytical queries that would be slow against a live peer.

The index starts at the current epoch on its first run and moves forward. It can catch up within that epoch, follow the live network, and serve reads while ingestion continues.

## Run it locally

Requirements are Rust 1.85 or newer, Bash, and `curl`. The first script installs ClickHouse if it is missing.

```bash
scripts/dev-up.sh
scripts/smoke.sh
```

The API listens on `127.0.0.1:8080` by default. The health check and a tick query confirm the stack:

```bash
curl -sS localhost:8080/healthz
curl -sS localhost:8080/v1/status
curl -sS 'localhost:8080/v1/ticks?epoch=240&limit=25'
```

The OpenAPI document and the status dashboard are served from the same process:

```bash
open http://127.0.0.1:8080/docs
open http://127.0.0.1:8080/status
```

Set `QUBIC_PEERS` to choose the peers the indexer follows. `BIND` changes the listen address, `CLICKHOUSE_URL` and `CLICKHOUSE_DB` point at storage, and `ALLOW_BROADCAST` controls the optional transaction broadcast route. Stop the stack with `scripts/dev-down.sh`; add `--wipe` to delete local ClickHouse data.

<Callout type="note" title="Ingest is the trust boundary">
  The service verifies peer data before writing it. Once a tick is in ClickHouse, the read path serves it without repeating the peer check. Review the peers and verification settings when you deploy, not on every query.
</Callout>

A self-hosted index is useful when you need a different retention window, a private network path, or a query surface that a public service does not expose. The tradeoff is operational: peers, storage, and migrations become your responsibility.
